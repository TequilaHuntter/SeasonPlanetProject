# Season Planet 技术设计 v0.1

本文用于第一版原型开发。已确认的方向作为实现依据；标注“建议默认”的规则和数值用于试玩验证，可以调整，不代表最终平衡。

## 1. 设计要点

### 1.1 产品与核心循环

产品是一款星球种植主题的番茄钟。先开发浏览器 H5，再复用核心逻辑制作 Windows 桌宠版本，小红书小工具作为后续适配渠道。

核心循环：购买种子 → 在星球上种植 → 专注 30 分钟 → 结算一季 → 收获作物并改变生态 → 出售作物或星球 → 继续种植。

玩家通过植物调整氧气、含水量、温度、丰饶度四项指标。经营收入用于购买种子；星球改造成果体现在环境外观和出售价格上。

### 1.2 第一版范围

- 固定一种初始星球，划分四块种植区，每块种植一种植物。
- 春、夏、秋、冬循环，每完成一个 30 分钟专注阶段推进一季。
- 四项生态指标全部实现。
- 商店包含购买种子、出售作物、出售星球。
- 出售星球后保留金币，获得同一种初始星球。
- 提供计时、暂停、继续、本地存档、重置存档功能。
- 星球先用轻量 2D 表现，展示地块、植物阶段和季节色彩。

第一版暂不做随机灾害、订单、钓鱼、采矿、联网、云存档、账号、支付和排行榜。

### 1.3 回合规则（建议默认）

1. 准备阶段：买种子、种植、移除植物、出售作物和星球。
2. 点击开始后锁定本季种植方案，进入专注阶段；期间可暂停或放弃本次计时，不执行经营操作。
3. 累计专注达到 30 分钟，按当前季节结算一次，再切换到下一季。
4. 展示收获、指标变化及星球估值，停在下一季准备阶段，不自动开始下一轮。
5. 放弃本次计时只清零本季计时，不推进季节、不产生收获，不清除已有植物。

结算顺序固定为：读取本季生态快照 → 判断植物适应性 → 累加植物改造效果 → 计算产出 → 更新指标并限制取值范围 → 增加库存 → 推进季节 → 更新估值 → 保存。

所有植物以同一份结算前生态快照判定适应性，避免地块顺序影响结果。改造效果在本次结算后生效，影响下一回合。第一版植物当季适应即可产出；不适应时休眠，无产出、无改造效果，不死亡。植物跨季保留，可主动移除，移除不退款。

### 1.4 计时与离开规则

网页原型建议默认：切到后台、锁屏或关闭页面时暂停；回来后手动继续。刷新或重开恢复已保存进度，关闭期间不补算回合。

桌宠版目标：切换其他软件、收起管理面板时继续计时；主动暂停、退出应用或电脑休眠时暂停；不自动补算退出或休眠期间的时间。

计时策略与玩法逻辑分离，两个版本可使用不同的离开策略。网页只能依据页面可见性等浏览器事件近似识别离开，不能证明玩家正在专注，也不能保证识别所有系统锁屏情况。

### 1.5 出售星球（建议默认）

- 仅准备阶段允许出售；出售前确认价格和处理内容。
- 当前星球及其地块植物一起出售，植物不另计回购价。
- 金币、仓库作物及未使用种子保留。
- 新星球恢复初始指标、空地块、春季和零计时。
- 初始星球免费发放，未完成改造时售价为零；第一版只出售生态改善产生的价值，防止反复出售免费星球刷钱。
- 完成至少一个回合且售价大于零才可出售。

## 2. 配置内容

配置用带类型校验的静态数据维护，编辑后构建进应用；运行时不依赖在线表格或接口。后续可增加表格导入工具，首版先直接维护配置。

### 2.1 全局配置

| 字段 | 用途 | 建议默认 |
| --- | --- | --- |
| configVersion | 配置版本 | 1 |
| focusDurationSeconds | 单季专注时长 | 1800 |
| seasonOrder | 季节顺序 | spring、summer、autumn、winter |
| plotCount | 地块数量 | 4 |
| initialCoins | 初始金币 | 100 |
| hiddenPolicy | 网页离开策略 | pause |
| unsuitableBehavior | 环境不适行为 | dormant |

开发模式可单独设置 10 秒回合和手动快进，仅用于验证，不出现在正式用户流程中。

### 2.2 生态指标配置

第一版四项指标统一使用 0—100 的游戏刻度，温度不标为摄氏度，避免与现实物理量混淆。每个指标配置 id、显示名、最小值、最大值、初始值、理想下限、理想上限、估值权重。

| 指标 | 初始值 | 理想区间 | 估值权重 |
| --- | --- | --- | --- |
| 氧气 oxygen | 20 | 45—65 | 0.25 |
| 含水量 water | 25 | 45—65 | 0.25 |
| 温度 temperature | 65 | 45—60 | 0.25 |
| 丰饶度 fertility | 15 | 45—70 | 0.25 |

以上均为试玩初值。指标越接近理想区间越好，不采用“越高越好”。第一版季节影响作物是否适应和视觉表现，不额外自动修改生态数值，避免同时引入过多变量。

### 2.3 种子配置

| 字段 | 含义 |
| --- | --- |
| id / name / description | 唯一标识、名称、介绍 |
| buyPrice | 单颗种子价格 |
| allowedSeasons | 适应季节列表 |
| environmentRequirements | 四项指标允许区间，未指定项不限制 |
| environmentDelta | 适应时每回合对四项指标的增减 |
| cropId | 对应收获作物 |
| yieldPerRound | 每个适应回合的产量 |
| visualKey | 本地植物素材或绘制样式标识 |

建议第一版设置六种植物：四种分别改造四项指标，一种低收益耐受作物，一种高收益但环境要求较高的作物。初始商店至少有一种玩家买得起且能在初始星球生长的植物。

植物需明确展示价格、适应季节、环境要求、预计产出和生态影响。购买进入种子库存，种植消耗一颗，库存不足或金币不足时禁止操作并显示原因。

### 2.4 作物配置

字段包括 id、name、sellPrice、visualKey。作物进入仓库后由玩家主动出售，支持单件和全部出售，售价不随季节波动。金额和数量使用非负整数。

### 2.5 星球配置与估值

星球配置包括 id、name、initialEnvironment、plotCount、visualKey、valuationProfileId。

估值配置包括每项理想区间、权重、maxImprovementValue、minimumCompletedRounds。建议最大改造价值暂设为 500 金币，至少完成 1 回合。

估值算法：

1. 单项在理想区间内，评分为 1。
2. 低于理想下限 L：评分为 value / L。
3. 高于理想上限 U：评分为 (100 - value) / (100 - U)。
4. 单项评分限制在 0—1；加权得到当前宜居评分 S。
5. 从初始指标计算初始评分 S0。
6. 售价 = 向下取整[maxImprovementValue × max(0, (S - S0) / (1 - S0))]。

配置校验要求 0 < L ≤ U < 100、权重总和为 1、S0 < 1。初始售价为零，理想状态达到最大改造价值。此公式只用于第一版，待试玩后调整收益与所需回合数。

### 2.6 配置校验

启动开发预览和构建时检查：标识唯一、引用存在、数值有限、价格和产量为合法整数、区间合法、素材存在、至少一种初始可种植物、估值权重合法。无效配置报出具体字段，不静默使用零值。

## 3. 实现方式

### 3.1 建议技术方案

- TypeScript + Vite：网页项目和构建工具。
- HTML/CSS + Canvas 2D：管理界面、星球绘制和轻量动画。
- 本地存储：网页原型保存进度。
- Electron：后续 Windows 桌宠外壳，复用网页界面与游戏逻辑。

第一版不需要 Unity、UE 或 Godot，也不需要服务器。游戏数据、结算、计时与显示层分离，避免后续桌宠适配重写玩法。

### 3.2 模块划分

| 模块 | 职责 |
| --- | --- |
| config | 配置数据、类型和校验 |
| game-core | 种植、适应判断、回合结算、估值、交易 |
| timer | 专注计时、暂停恢复、完成事件 |
| state | 当前存档和合法状态转换 |
| storage | 存档读写、备份和版本迁移 |
| ui | 星球、商店、仓库、计时和结算面板 |
| platform | 浏览器与未来桌面版的能力适配 |

游戏核心以明确输入产生结果，不访问页面、不直接读写存储、不依赖计时器，便于验证和复用。

### 3.3 状态与存档

计时状态：准备 ready → 专注 running ↔ 暂停 paused → 结算 settling → 准备 ready。结算阶段禁止重复交互。

存档字段：schemaVersion、configVersion、revision、金币、种子库存、作物库存、星球类型、生态指标、四块地植物、当前季节、累计完成回合数、计时状态、累计专注时长、roundId、lastSettledRoundId、更新时间。

只保存必要状态，估值和界面标签通过配置与状态计算，避免重复数据不一致。恢复存档时将 running 转为 paused。

### 3.4 计时与一次性结算

倒计时显示可定期刷新，但实际进度根据本次运行段的单调时钟差值计算，不依赖“每秒减一”，避免页面卡顿造成时间误差。

暂停时累加当前运行段的时间并保存。网页可见时每隔约 5 秒保存进度，并在暂停、种植、交易及结算后立即保存；异常关闭可能损失最近几秒，不承诺完全无损。

结算以 roundId 防止重复。同一回合的收获、生态变化、季节推进和已结算标记组合成新状态，一次保存成功后再显示完成；保存失败则保留待重试状态并提示用户，不提前发放奖励。

网页原型只支持同一存档单窗口运行。使用运行实例标识和存档 revision 检测多窗口冲突，后打开的窗口提示关闭其他实例，不允许并行写入。

### 3.5 本地存档策略

- 存档使用独立键名，保留上一份有效备份。
- 读取后校验结构和数值；损坏时尝试备份，不直接覆盖原始数据。
- 版本不兼容时提供明确提示，后续通过 schemaVersion 执行迁移。
- 重置需要确认。
- 第一版属于本机存档，清理浏览器数据可能丢失进度；网页与桌面版本不会天然同步。
- 小红书容器存储不保证永久保留，不把长期经营数据的可靠保存作为该渠道的首版承诺。

### 3.6 Windows 桌宠后续适配

提供完整管理窗口与小星球悬浮模式。悬浮模式显示星球、剩余时间和暂停入口，支持拖动、置顶开关及返回管理界面。不同视图共用一个权威游戏状态和计时实例。

桌面主进程负责计时与系统休眠事件，窗口收起或失去焦点不暂停；休眠、退出时保存并暂停。程序退出后不生长。置顶由用户选择。

桌面版加载本地打包资源，关闭页面 Node.js 集成，通过有限接口调用系统能力。

### 3.7 小红书适配边界

根据已查阅的官方能力清单，小工具使用纯 HTML/CSS/JS，不支持联网请求、WebAssembly 和 Worker，所有素材需随包提供。采用不依赖这些能力的 2D 实现；配置应直接构建进脚本，避免通过 fetch 加载。

后续增加分享纪念卡，可适配保存相册与唤起笔记发布页能力。小工具不提供 Windows 桌宠悬浮功能；发布资格、包体规格及实际审核要求在适配时核实。

## 4. 工作顺序与验收

### 阶段一：核心原型

完成配置、固定星球、四块地、商店、仓库、四项指标和单回合结算。用开发快进验证“买种 → 种植 → 收获 → 售卖 → 改造 → 出售星球 → 新星球”的完整循环。

### 阶段二：番茄钟与存档

接入正式 30 分钟计时、暂停继续、离开暂停、刷新恢复和结算展示。验证计时完成只结算一次，多窗口不覆盖进度。

### 阶段三：试玩与表现

加入季节和植物动画，完善操作反馈，通过试玩调整初始资金、种子成本、收益和改造速度。先验证是否愿意持续专注并回来收获，再扩充内容。

### 阶段四：渠道扩展

根据试玩结果选择 Windows 桌宠或小红书小工具适配顺序，不同时扩展两个渠道。

### 必须通过的核心检查

- 余额不足、库存不足、地块占用时不能购买或种植。
- 多株植物按同一生态快照判断，结果不随地块顺序改变。
- 休眠植物不产出、不改造；指标不越过上下限。
- 暂停、刷新和重新进入不会提前完成或重复结算。
- 出售初始星球无法刷取免费金币。
- 出售后资产保留与星球重置符合规则。
- 存档失败、损坏及多窗口冲突有明确反馈。
- 桌面和手机窄屏均能完成核心操作。

## 5. 开工所需内容

现有信息足以开始功能原型，可暂用几何星球、植物占位图和试玩配置，不需要先准备完整美术。

开工前建议确认本文件的三项默认规则：环境不适先休眠不死亡；专注期间不调整种植；星球售价只计算改造增值。其余数值可以边试玩边改。

后续由用户选择美术方向、植物命名和音效偏好；这些不阻塞核心功能开发。
